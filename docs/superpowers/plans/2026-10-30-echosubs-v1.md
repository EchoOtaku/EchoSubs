# EchoSubs 首版 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付可离线使用的 Windows 和 Android 个人订阅账本，同时具备局域网直连、WebDAV 加密同步、到期提醒和独立备份恢复。

**Architecture:** 单个 Flutter 应用，共享 Dart 领域逻辑，以 SQLite 保存每台设备的账本、不可变变更记录和同步状态。统一的变更引擎负责事务、因果依赖、冲突及去重，两条传输通道仅交换相同密文对象。平台适配器承担密钥存储、局域网、通知和文件导入导出，不引入自建云后端。

**Tech Stack:** Flutter 3.47 stable 系列、Dart >=3.11 <4、Drift、cryptography、dart:io、Flutter 平台插件；候选依赖版本及安装闸门见下文。

**Spec:** [已批准的首版设计](../specs/2026-10-19-echosubs-design.md)。执行者必须同时阅读设计与本计划。

## Global Constraints

- 支持 Windows 和 Android，能够双端同步。
- 同时提供局域网直连与 WebDAV 同步；两种方式独立开关，也能同时启用。
- 数据本地优先，离线可查看和编辑；手机使用本地预约提醒。
- GitHub 仓库先设为私有，未经用户明确要求不转为公开。
- 首版按币种分别汇总，不在没有汇率依据时把人民币、美元等直接相加；自动汇率换算不纳入首版。
- 自动续费只是用户记录的预期行为，不代表第三方已经扣款，不自动生成实际付款或延长已经确认的权益。
- 首版不自动清理删除标记和变更历史，避免长期离线设备回来时失去判断依据；后续压缩历史需要单独设计。
- 本机环境沿用唯一清单 `D:\Workspaces\Personal\MyPCConfig\AGENT_ENVIRONMENT.md`，不在本项目复制环境清单。
- 新增 SDK、修改系统配置、申请云权限或发生费用之前分别取得授权。
- 不包含自动扣款、账单抓取、iOS、公网穿透、公共中继、强制账号、遥测或应用商店上架。
- 原始设计的本地 SQLite 不额外加密边界保持不变；不能把云端加密宣传为本地文件已加密。
- Git 提交格式为 `type(scope): 中文消息`；不得提交真实账本、密钥、凭据、签名文件或本机环境副本。

## Review Focus

- 月末、闰年和夏令时叠加：周期不漂移，提醒不因时区跳变重复；任务 1、9 用断言覆盖。
- 同一批变更从两条通道乱序到达并遇到崩溃：只应用一次，付款与权益不会部分成功；任务 3、5、8 覆盖。
- 两台设备离线续费或删除后相互同步：保留冲突，争议付款不重复计入，旧删除不复活；任务 5 覆盖。
- 恶意或不规范 WebDAV 返回路径、跳转、半文件或同 ID 异内容：不泄露凭据，不越界读写，不降级覆盖；任务 2、6 覆盖。
- 错误恢复密钥、拒绝通知权限、取消文件选择：原账本完整可用，错误可见，不假报已恢复或已启用提醒；任务 9、10 覆盖。

核心类型由任务 1 定义，之后不得私自改名：ID 均为 128 位安全随机数的小写十六进制字符串；`CivilDate(year, month, day)` 验证真实日期；`Money(currency, minorUnits, scale)` 使用整数最小单位，JSON 中金额为十进制字符串，同币种不同精度拒绝混算。

`Subscription` 字段为 `id, name, provider, purchaseChannel, paymentMethod, websiteUrl, notes, categoryId, status, billingType, price, cycle, cycleAnchor, startDate, entitlementEnd, nextRenewalDate, autoRenew, reminderRule`；可未知的价格和日期允许为空。`BillingType` 为 `fixed, metered, lifetime`，`SubscriptionStatus` 为 `active, paused, archived`，删除由版本记录表示。`BillingCycle(unit, count)` 的 unit 使用 `CycleUnit {day, week, month, year}`，count 必须大于零。

`Payment` 字段为 `id, subscriptionId, amount, paidOn, periodStart, periodEnd, notes`；零元合法，负数首版拒绝，退款不伪装成付款。`LedgerConfig(id, timeZoneId)`、`Category(id, name)`、`ReminderRule(daysBefore, localHour, localMinute)` 为同步实体；默认规则为 `[7,3,1]`、`9:00`。

`EntityRef(kind, id)` 中 kind 为 `subscription, payment, category, ledgerConfig`。`Mutation(ref, parentBatchIds, value)` 保存完整新值，value 为 null 表示删除；新实体 parents 为空。`ChangeBatch(id, ledgerId, deviceId, createdAtUtc, mutations)` 是原子业务单位。`LedgerProjection` 包含已确认实体、`conflicts` 和 `pendingBatchIds`；`Conflict(id, competingBatchIds, affectedRefs)` 不得丢弃双方候选内容。`LedgerId, DeviceId, EntityId, BatchId` 定义为 String 类型别名；不可变值对象实现值相等，正文序列化不依赖 Map 插入顺序。

所有跨模块接口采用下列返回约定：可恢复错误抛出 `EchoFailure(code, safeMessage)`，code 为 `validation, locked, incompatible, authentication, integrity, conflict, unavailable, cancelled`。异常和日志不携带秘密或完整私人条目；不吞异常后返回成功。`CancellationToken` 暴露 `bool get isCancelled`。

## 计划自查与交付标准

| 设计要求 | 对应任务 |
| --- | --- |
| 日期、费用、来源、续费与历史 | 1、3、4 |
| 无账号离线、中文双端界面 | 3、4 |
| 加密、密钥、恢复及本地保护边界 | 2、10 |
| 原子变更、双通道去重、删除、冲突收敛 | 3、5、8 |
| 局域网与 WebDAV 两种完整通道 | 6、7、8 |
| 手机提醒、权限、重启核对与同步状态 | 8、9、11 |
| 独立备份、导出和非覆盖恢复 | 10 |
| 私有仓库、敏感信息隔离、双端构建 | 1、11 |

每个任务使用红灯测试、最小实现、绿灯复核及独立提交。接口变更先修改计划中的生产者和消费者约定，不能由某一执行者单方面改名。所有任务复选框仍未勾选：本文件是实现计划，不是运行或验收结果。

计划需要用户审核并选择执行方式：逐任务独立子代理实现和审查，或由主代理连续实现后统一独立审查。鉴于同步、加密与恢复错误可能造成数据损失，建议逐任务审查；它需要更多上下文和调用成本。无论选择哪种方式，安装环境和真实服务接入仍须分别授权。
