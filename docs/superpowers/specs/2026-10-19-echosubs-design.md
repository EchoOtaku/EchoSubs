# EchoSubs 订阅簿首版设计

状态：用户已于 2026-10-30 批准设计。设计日期：2026-10-19。

EchoSubs 用于统一记录个人的域名、服务器、对象存储、影音会员和其他数字服务。Windows 端便于集中整理，Android 端便于随身查看和接收到期提醒。两端各自保有完整数据；不要求自建业务服务器，也不强制注册应用账号。

## 已确认的方向

- 支持 Windows 和 Android，能够双端同步。
- 同时提供局域网直连与 WebDAV 同步；两种方式独立开关，也能同时启用。
- 数据本地优先，离线可查看和编辑；手机使用本地预约提醒。
- GitHub 仓库先设为私有，未经用户明确要求不转为公开。
- 项目名 EchoSubs，中文名订阅簿；本文为历史产品设计，当前实现与验收以仓库 README 和 docs/build/acceptance.md 为准。

以下首版范围、技术安排和安全边界已获用户批准。设计批准不代表应用已经实现，也不单独授权安装开发环境或接入真实网盘。

## 首版范围

| 能力 | 首版内容 |
| --- | --- |
| 订阅管理 | 创建、编辑、搜索、分类、归档和删除订阅；记录服务商、购买渠道、支付方式、网址和备注 |
| 日期与周期 | 分开记录开始日期、权益到期日期、下一次续费日期、续费周期和自动续费标记 |
| 费用 | 固定周期、按量计费、一次性买断三种类型；支持不同币种 |
| 付款记录 | 手动登记实际付款金额、付款日期、覆盖的权益期间和备注，保留历史 |
| 展示 | 即将到期列表、日历、分类总览、预计月年支出与实际支出 |
| 提醒 | 提前若干天提醒、应用内逾期提示、通知权限状态和测试提醒 |
| 同步 | 局域网扫码配对、WebDAV 加密同步、待同步状态、冲突处理、手动重试 |
| 数据恢复 | 加密备份导出与恢复、恢复密钥、带版本的结构化数据导出 |

不纳入首版：自动购买或扣款、自动登录第三方服务抓取账单、多人合租分账、iOS、浏览器客户端、厂商推送 SDK、互联网穿透或公共中继、应用商店上架。

## 使用与展示

主导航分为总览、订阅、日历、付款记录、设置。桌面采用适合宽屏的信息布局，手机采用适合触控的布局，复用数据与业务规则，不把桌面界面简单缩小。

总览首先展示近期到期条目、尚未处理的逾期条目与同步异常，再展示费用。预计支出和实际支出始终分开标识。没有费用数据的条目仍可管理日期与提醒。

订阅详情区分三个概念：服务由谁提供、从哪里购买、用什么支付。例如服务商为腾讯视频，购买渠道为兑换码，支付方式可以为空。备注用于补充信息，不充当唯一的结构化字段。

同步设置展示每条通道的启用状态、最近一次成功时间、待上传数量、待处理冲突和错误原因。成功的标准是此次上传与拉取均完成并应用可合并的数据，而不是仅连通网盘。

## 日期和费用规则

1. 续费周期支持正整数个日、周、月或年；季度和半年分别是三个月和六个月。月末日期按原始周期锚点计算，目标月不存在该日时取月末，避免二月截断后永久漂移。
2. 权益到期日期包含当天。下一续费日期独立保存，不强行等于权益到期日期；买一年送三个月可以准确表达。
3. 日期按账本时区解释。新账本以创建时设备时区为初始值并保存，设备旅行或换时区不自动改变账本时区；变更账本时区需要用户操作并重排提醒。
4. 自动续费只是用户记录的预期行为，不代表第三方已经扣款，不自动生成实际付款或延长已经确认的权益。预计扣款日期可向后推算，但保留未确认状态。
5. 记录一次续费时，实际付款和权益期间由用户确认。付款记录与订阅日期的对应调整作为同一次业务变更原子保存。
6. 固定周期费用可折算为月年预计费用，并明确标为估算；按量计费不自动当作固定价格，也不把上月费用当作未来承诺；买断费用只计入实际支出。
7. 金额用定点或十进制定量表示，不使用二进制浮点数累加账单。首版按币种分别汇总，不在没有汇率依据时把人民币、美元等直接相加；自动汇率换算不纳入首版。
8. 暂停或归档的条目保留历史，不继续按活跃订阅生成提醒和费用预测。删除使用可同步的删除标记，恢复必须是显式操作。

## 技术结构

客户端采用 Flutter 和 Dart，共享领域逻辑与主要界面代码；平台通知、安全存储、扫码与局域网能力通过独立适配层实现。本地使用 SQLite，作为每台设备的可查询数据存储，不直接通过网盘复制正在使用的数据库文件。

| 模块 | 单一职责 |
| --- | --- |
| 领域逻辑 | 日期周期、权益、费用、付款和提醒规则，不依赖网络或界面 |
| 本地存储 | 数据事务、版本迁移、待同步变更、已接收变更与冲突 |
| 同步引擎 | 校验账本身份、版本依赖、去重、合并、删除与重试 |
| 局域网通道 | 已配对设备之间的发现、认证连接和数据传输 |
| WebDAV 通道 | 使用用户指定的存储目录上传和下载加密变更对象 |
| 加密与密钥 | 账本密钥、设备授权、密文完整性与恢复 |
| 提醒适配 | 根据当前本地状态登记、取消和重建系统提醒 |
| 界面 | 条目与日历展示、录入、冲突处理、权限与同步状态 |

两条通道只负责传输，不各自实现一套数据合并规则。同步失败不影响本地保存，用户不需要为了基本功能先配置网盘。

## 同步数据和冲突

每个账本、设备、实体和变更批次都有稳定的唯一标识。变更带协议版本、实体版本依赖和创建时间；创建时间用于展示，不作为判断谁覆盖谁的唯一依据。

本地修改时，业务数据和待发送变更在同一数据库事务中提交。变更的编码和加密结果生成一次后持久保存，两条通道和后续重试使用同一对象。接收时，变更应用与已应用标识也在同一事务中提交。一次业务变更中的订阅与付款调整不可拆成部分成功。

- 同一变更经局域网和 WebDAV 重复到达，只应用一次。
- 依赖尚未到达的变更暂存，补齐后再应用；中断、重启和重试不能漏改或重复记账。
- 不同条目的独立修改可以合并。同一条目的并发版本保留为冲突，不按设备时间静默选胜者。用户选择一个版本或编辑合并结果后，生成明确引用双方版本的解决记录。
- 删除与编辑同时发生也作为冲突处理，禁止旧设备无提示地复活已删记录。
- 涉及付款或权益的冲突必须显示未确认状态及争议内容，不能把互斥的续费操作全部当作已确认付款叠加。
- 首版不自动清理删除标记和变更历史，避免长期离线设备回来时失去判断依据；后续压缩历史需要单独设计。
- 两条通道必须指向同一账本。连接到不同账本的网盘目录时停止同步，不默认合并；新设备通过明确的加入账本流程接入。

应用启动、进入前台以及用户点击同步时尝试同步已启用的通道。连接期间可传输新变更，但不承诺应用关闭或系统限制后台时仍然实时同步。

## 局域网同步

首版仅面向同一可达局域网或手机热点。首次连接采用短期有效、一次性扫码配对，并要求双方确认设备身份；不依赖公网发现、公共中继或外部账号。

配对后通过有身份认证的加密连接传输，并校验账本身份；不把二维码中的一次性授权信息当作长期明文共享密码。已有账本的加密密钥只通过经过确认的安全配对过程传给新设备。

局域网发现不可用时允许使用二维码中的地址直接连接。连接失败时说明网络隔离、应用未运行或防火墙等可能原因，不自动开放公网端口，也不自动关闭 Windows 防火墙。首版以双方打开应用时可用为验收条件。

## WebDAV 同步

用户主动配置 HTTPS WebDAV 地址、独立的应用目录和凭据。启用前显示将上传的数据类别及加密边界，不代用户注册账号、购买存储或选择收费套餐。

WebDAV 只保存账本加密数据，不提供业务 API 或应用账号系统。每个变更批次使用独立、不可变的对象名称；不让多台设备反复覆盖同一个数据库或可变索引文件。上传中断或对象不完整时，不应用该对象，保留重试状态；同一个已保存的加密对象可安全重传。

只读取和写入该账本的专用目录，不扫描或改动用户其他网盘文件。遇到认证失败、证书错误、空间不足、协议不兼容或无法确认对象完整性时停止对应同步并给出错误，不回退为 HTTP、明文传输或覆盖冲突文件。不得向跨站重定向转发凭据。

首版不单独集成 OneDrive、Google Drive 或 Dropbox 的专用 API。WebDAV 通道提供无自建后端的远程同步，不称为完全不依赖云端。

## 隐私和恢复边界

- 不强制应用账号，不上传遥测，不接入广告或分析服务。
- WebDAV 采用端到端的认证加密，密钥属于账本而不是某一台设备；云端不保存可直接解密账本的秘密。对象大小、数量和访问时间等存储元数据仍可能可见。
- 使用成熟密码库，不自行设计加密算法。协议和加密格式带版本，具体依赖与互操作测试在实现计划中锁定。
- 账本密钥、设备凭据和 WebDAV 密码交由各平台的安全存储保存；日志、诊断信息、Git 仓库和普通导出文件不能包含这些秘密。
- 每个账本创建一份可离线保存的恢复密钥，并解释丢失风险。账本元数据可保存经恢复密钥封装的账本加密密钥、账本标识和格式版本，但不保存明文恢复密钥。若所有设备及恢复密钥都丢失，仅有云端密文也不能找回数据。
- 首版本地 SQLite 文件不另做数据库文件级加密，依赖操作系统用户权限和设备锁屏保护；端到端加密不代表已保护被攻陷或已解锁设备上的明文。这是本次已批准设计的安全边界。
- 禁用某设备的局域网配对只阻止后续直连，不意味着它遗忘已有数据或密钥。首版不承诺远程擦除或完整设备撤销；设备遗失时应停用旧网盘凭据，并通过安全备份建立新账本和新密钥。
- 同步不是备份。加密备份独立保存业务数据、协议版本、尚未解决的冲突和恢复所需元数据；同一账本的备份沿用该账本恢复密钥，不在每次导出时生成一把不同的恢复密钥，也不把明文密钥写进备份。
- 加入已有账本时，恢复密钥用于验证并解封该账本密钥，然后拉取现有变更，不创建另一个账本身份。从备份恢复则先校验并展示内容，默认导入为独立的新账本身份，生成新账本密钥和恢复密钥，不自动上传覆盖旧账本；其他设备需重新加入新账本，直接替换当前账本必须另行明确确认。
- 结构化明文导出仅在用户主动选择并确认内容包含私人订阅信息后执行，不默认保存到项目仓库。

## 到期提醒

提醒由手机本地安排，不依赖电脑常开或 WebDAV 随时可达。默认建议提前 7 天、3 天、1 天在账本时区上午约 9 点提醒，用户可以按条目修改。按日提醒优先采用不精确预约，不为了首版功能默认索取精确闹钟特殊权限。

编辑、删除、冲突解决、同步应用、设备重启恢复和账本时区调整后，都根据最新本地数据重新核对提醒；同一条目同一天同一提醒规则不得重复通知。重启恢复仍受系统是否允许执行影响，应用再次打开时必须补做核对。

通知权限关闭时，在界面中明确提示，不能仍显示提醒正常；提供测试提醒。强行停止、省电限制或长期不打开应用可能影响提醒，不承诺必达。Windows 首版可在应用运行时提醒，不默认增加开机启动或常驻后台服务。

手机尚未收到的电脑修改不能影响本地提醒。因此同步状态与上次同步时间必须可见；涉及到期日的未解决冲突使用明确的待确认提示，不能表现为日期已唯一确定。

## 备份和发布隔离

本地仓库仅保存源码、文档、构建配置和虚构测试数据。真实账本、导出、数据库、恢复密钥、网盘凭据、签名私钥和本机配置全部排除在版本控制之外。私有仓库不是保存秘密的替代方案。

GitHub 目标是私有仓库；发布安装包不等于公开仓库。Android 签名密钥必须在发布前制定独立备份方式，不能生成后只放在临时构建目录。

本机环境遵循仓库外的唯一环境清单，不在本项目复制机器配置。新增 SDK、修改系统配置、申请云权限或发生费用之前分别取得授权。

## 验收条件

| 场景 | 必须满足的结果 |
| --- | --- |
| 无网络启动两端 | 可查看、创建、修改并持久保存订阅，重启应用后数据不丢失 |
| 周期与权益 | 月末、闰年、赠送时长、买断和按量费用分别符合日期与费用规则 |
| 自动续费标记 | 不自动制造已付款记录，预期费用和实际支出可区分 |
| 局域网首次配对 | 需双方确认，其他设备无法未经授权读取账本 |
| WebDAV 单独启用 | 电脑上传后关闭，手机随后能拉取并应用；网盘对象不含明文业务字段 |
| 双通道重复传输 | 同一批变更只应用一次，无重复付款和重复提醒 |
| 双端离线并发修改 | 产生可见冲突，解决后两端收敛，双方原始内容有记录 |
| 删除与长期离线 | 旧设备重新连接不会静默复活条目，删除编辑冲突可以处理 |
| 崩溃与乱序 | 上传半途、应用事务中断、依赖乱序和重试不造成部分付款或漏改 |
| 加密与错误凭据 | 错误密钥、篡改对象、错误账本、无效证书或凭据被拒绝，原数据保持可用 |
| 手机提醒 | 真机验证授权、测试通知、日期变更、删除、重复同步与重启后的提醒核对 |
| 恢复 | 在干净的应用数据环境中通过备份和恢复密钥找回内容，不覆盖原账本 |
| 双端交付 | Windows 可运行构建与 Android 可安装构建分别完成安装和核心流程测试 |
| 版本控制 | 提交内容只包含允许的项目文件，不包含真实私人数据或秘密 |

真机通知验收需要用户提供手机型号和系统版本；真实 WebDAV 互操作验收需要用户主动提供测试端点或配置测试账号。未取得这些条件时，分别报告已通过的模拟测试和仍未验证的设备行为，不声称已全面兼容。

## 后续工作顺序

设计已获批准，下一步审核按任务拆分的实现计划并确认执行方式。实现先后为本地账本和日期测试、统一同步引擎、两种传输通道、提醒与恢复、双端打包验收；两种同步都属于首版范围，不以只完成一种代替交付。

当前阶段不创建 GitHub 仓库、不生成 Flutter 工程、不安装 SDK，也不连接真实网盘。设计和实现计划获批后，按私有仓库要求初始化远程开发空间；工具链缺失仍需单独安装授权。
